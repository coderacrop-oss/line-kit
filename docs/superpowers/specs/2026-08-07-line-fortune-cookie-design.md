# LINE OA Fortune Cookie Game — Design

**วันที่:** 2026-08-07
**สถานะ:** อนุมัติดีไซน์แล้ว รอเขียนแผน implementation

---

## 1. เป้าหมาย

เกมเสี่ยงทายคุกกี้เสี่ยงทายใน LINE Official Account เล่นจบในหน้าแชท ไม่มีหน้าเว็บ
จุดประสงค์คือความสนุกและ engagement ล้วน ๆ ไม่มีของรางวัล ไม่เก็บข้อมูลผู้ใช้

**เกณฑ์ว่าสำเร็จ**

- ผู้ใช้พิมพ์คำเรียกในแชท แล้วได้ตารางคุกกี้ 3×3 ภายในไม่กี่วินาที
- แตะคุกกี้ 1 ชิ้น แล้วได้คำทำนายที่ผูกกับชิ้นนั้นจริง ๆ (ชิ้นต่างกันได้คำทำนายต่างกัน)
- กด "เสี่ยงใหม่" วนเล่นได้ไม่จำกัด
- ค่าใช้จ่ายรวมตลอดการพัฒนาและใช้งาน = 0 บาท

## 2. ข้อจำกัดที่ตายตัว

### 2.1 ต้องฟรีทั้งหมด

| ส่วน | บริการ | ทำไมถึงฟรี |
|---|---|---|
| Hosting | Vercel Hobby | แผนฟรี รองรับ Next.js route handler และให้ HTTPS |
| Messaging | LINE Messaging API | **ข้อความแบบ reply ฟรีไม่จำกัด** — LINE คิดเงินเฉพาะ push / multicast / broadcast |
| Database | ไม่มี | ดีไซน์เป็น stateless เต็มรูปแบบ |
| Test | Vitest | โอเพนซอร์ส |

**กฎเหล็ก: ห้ามใช้ Push API / Multicast / Broadcast ในโค้ดนี้เด็ดขาด**
ทุกการตอบกลับต้องผ่าน Reply API ด้วย `replyToken` เท่านั้น ถ้าวันใดต้องส่งข้อความที่ไม่มี
`replyToken` ให้ถือว่าฟีเจอร์นั้นอยู่นอกขอบเขต ไม่ใช่ให้เปลี่ยนไปใช้ push

### 2.2 ข้อจำกัดจากแพลตฟอร์ม LINE

- **แก้ไขข้อความที่ส่งไปแล้วไม่ได้** — ตอนผู้ใช้เลือกคุกกี้ การ์ดตารางเดิมจะค้างในแชท
  บอทตอบเป็นข้อความใหม่ต่อท้าย ไม่ใช่แก้ของเดิม (เป็นพฤติกรรมปกติของบอท LINE ทุกตัว)
- **`replyToken` ใช้ได้ครั้งเดียวและหมดอายุใน 30 วินาที** — handler ต้องตอบให้จบเร็ว
  ห้ามมีงานหนักหรือ I/O ที่รอนานก่อนเรียก reply
- **`postback.data` ยาวได้ไม่เกิน 300 ตัวอักษร** — พอเหลือเฟือสำหรับสิ่งที่เราเข้ารหัส
- **`postback.data` มาจากฝั่งผู้ใช้** ผู้ใช้ที่ตั้งใจแกล้งสามารถส่งค่าที่เราไม่ได้สร้างเข้ามาได้
  จึงต้อง validate ทุกครั้ง (ดู §6.3)

## 3. สถาปัตยกรรม: Stateless พร้อมคำทำนายฝังในปุ่ม

ทางเลือกที่เลือกคือ **แจกคำทำนายตอนสร้างตาราง แล้วฝัง id ไว้ในปุ่มแต่ละชิ้น**

ตอนสร้างการ์ดตาราง เซิร์ฟเวอร์สุ่มคำทำนาย 9 ใบไม่ซ้ำ แล้วผูกไปกับปุ่มทั้ง 9 ช่องผ่าน
`postback.data` พอผู้ใช้แตะช่องไหน LINE จะส่ง id ของคำทำนายในช่องนั้นกลับมาเอง
เซิร์ฟเวอร์แค่อ่านค่าแล้วตอบ — **ไม่ต้องจำอะไรระหว่างสองข้อความเลย**

ผลที่ได้:

- การเลือกของผู้ใช้มีผลจริง ไม่ใช่ภาพลวง
- ไม่ต้องมี database ไม่ต้องมี session ไม่ต้องมี in-memory cache
- รีสตาร์ทเซิร์ฟเวอร์หรือสเกลหลาย instance ก็ไม่กระทบ
- **ตารางเก่าที่ค้างในแชทเมื่อวานยังกดได้ปกติ** ไม่มีสถานะให้หมดอายุ

ทางเลือกที่ตัดทิ้ง: สุ่มตอนกด (การเลือกไม่มีความหมาย เสน่ห์หาย) และเก็บสถานะใน DB
(เกินจำเป็นเมื่อไม่มีของรางวัลและไม่จำกัดสิทธิ์)

## 4. Flow

```
ผู้ใช้เพิ่มเพื่อน
  └→ follow event → การ์ดต้อนรับ + ปุ่ม "เสี่ยงทายเลย"

ผู้ใช้พิมพ์คำเรียก / กดปุ่ม "เสี่ยงทายเลย" / กด "เสี่ยงใหม่"
  └→ การ์ดตาราง 3×3 (แต่ละช่องซ่อนคำทำนายคนละใบ)
       └→ ผู้ใช้แตะ 1 ช่อง → postback: a=open&f=42
            └→ การ์ดคำทำนาย + ปุ่ม "เสี่ยงใหม่อีกครั้ง"
                 └→ postback: a=new → วนกลับไปตารางใหม่

ผู้ใช้พิมพ์อย่างอื่นที่ไม่รู้จัก
  └→ การ์ดใบ้วิธีเล่น + ปุ่ม "เสี่ยงทายเลย"   (ไม่ปล่อยให้เงียบ)
```

## 5. โครงสร้างโค้ด

แต่ละไฟล์มีหน้าที่เดียว ทดสอบแยกกันได้ ส่วนที่เป็นตรรกะเกมทั้งหมดเป็น pure function
ไม่แตะเน็ตเวิร์ก ทำให้เทสต์ไม่ต้องยิง LINE จริง

```
app/api/line/webhook/route.ts   POST handler — ตรวจลายเซ็น แล้วส่งต่อให้ handleEvent
lib/line/verify.ts              ตรวจ X-Line-Signature
lib/line/client.ts              เรียก Reply API (จุดเดียวในระบบที่ออกเน็ต)
lib/line/types.ts               type ของ webhook event และ Flex message
lib/game/fortunes.ts            คลังคำทำนาย 60 ใบ
lib/game/draw.ts                สุ่มคำทำนาย 9 ใบ (pure, รับ rng เข้ามา)
lib/game/postback.ts            encode / decode + validate postback data
lib/game/handler.ts             event → message ที่จะตอบ (pure)
lib/flex/grid.ts                สร้าง Flex การ์ดตาราง (pure)
lib/flex/fortune.ts             สร้าง Flex การ์ดคำทำนาย (pure)
lib/flex/prompt.ts              สร้าง Flex การ์ดต้อนรับ / การ์ดใบ้วิธีเล่น (pure)
```

`handler.ts` เป็นหัวใจ: รับ event เข้ามา คืน "ข้อความที่จะตอบ" ออกไป โดยไม่ส่งเอง
`route.ts` เป็นคนเอาผลลัพธ์ไปส่งผ่าน `client.ts` — แยกการตัดสินใจออกจากผลข้างเคียง
ทำให้เทสต์ตรรกะทั้งหมดได้โดยไม่ต้อง mock อะไรเลยนอกจาก rng

## 6. รายละเอียดแต่ละส่วน

### 6.1 คลังคำทำนาย (`lib/game/fortunes.ts`)

```ts
type Tone = 'daily' | 'funny' | 'inspire'

interface Fortune {
  id: number      // ไม่ซ้ำ ไม่เปลี่ยน ใช้อ้างอิงใน postback
  tone: Tone
  text: string    // ภาษาไทย 1–2 ประโยค
}
```

รวม **60 ใบ แบ่งโทนละ 20 ใบ**

| โทน | อารมณ์ | ตัวอย่าง |
|---|---|---|
| `daily` | ดวงรายวันกลาง ๆ | "วันนี้มีคนคิดถึงคุณอยู่ แต่เขาขี้อายเกินจะทัก" |
| `funny` | ตลก แซ่บ กวน ๆ | "ดวงการเงินวันนี้ดีมาก ถ้าคุณไม่เปิดแอปช้อปปิ้ง" |
| `inspire` | กำลังใจ ข้อคิด | "สิ่งที่คุณทำอยู่ยังไม่เห็นผล ไม่ได้แปลว่ามันไม่ได้ผล" |

`id` ห้ามเปลี่ยนหลังปล่อยใช้งาน เพราะการ์ดตารางเก่าที่ค้างในแชทอ้างอิง id เดิมอยู่
เพิ่มใบใหม่ให้ใช้ id ถัดไปเรื่อย ๆ ไม่ใช้ id ซ้ำของที่ลบไปแล้ว

### 6.2 การสุ่ม (`lib/game/draw.ts`)

```ts
function drawNine(rng: () => number): Fortune[]
```

- สุ่มโทนละ 3 ใบไม่ซ้ำ (3 × 3 = 9) แล้วสับตำแหน่งทั้ง 9 ช่อง
- **รับประกันว่าทุกตารางมีครบทั้ง 3 โทน** — คนเล่นจะไม่เจอตารางที่มีแต่มุกตลกล้วน
- รับ `rng` เข้ามาเป็นพารามิเตอร์ ค่า default คือ `Math.random`
  ทำให้เทสต์ส่ง rng ที่คาดเดาได้เข้าไปแล้วตรวจผลลัพธ์ตรง ๆ ได้

### 6.3 Postback (`lib/game/postback.ts`)

ใช้ `URLSearchParams` encode/decode

| การกระทำ | data |
|---|---|
| เปิดคุกกี้ | `a=open&f=<fortuneId>` |
| ขอตารางใหม่ | `a=new` |

ปุ่มแต่ละช่องตั้ง `displayText` เป็น `"ทุบคุกกี้ชิ้นที่ N"` เพื่อให้ในแชทของผู้ใช้
เห็นว่าตัวเองเลือกช่องไหน (เป็นแค่ข้อความโชว์ ไม่มีผลต่อตรรกะ)

**Validate เสมอ:** `f` ต้องเป็นจำนวนเต็มที่มีอยู่จริงในคลัง ถ้าไม่ใช่ — ไม่ว่าจะเพราะ
ผู้ใช้ปลอมค่า หรือเพราะเราลบคำทำนายใบนั้นทิ้งไปหลังปล่อยใช้งาน — ให้ตอบด้วยคำทำนาย
ที่สุ่มใหม่แทนที่จะโยน error ผู้ใช้ไม่ควรเจอหน้าจอพัง

### 6.4 หน้าตาการ์ด

**การ์ดตาราง** (`lib/flex/grid.ts`)

ไม่ใช้ปุ่มมาตรฐานของ Flex เพราะได้ลุคเป็นแถบยาว ใช้ `box` ที่ใส่ `action` ได้แทน
ทำเป็นไทล์สี่เหลี่ยมมุมมนวางเรียง 3×3 ได้ลุคตารางแบบซูโดกุจริง และไม่ต้องพึ่งไฟล์รูปเลย
(ไม่ต้องโฮสต์รูป = ไม่มีค่าใช้จ่ายเพิ่ม)

```
┌─────────────────────────┐
│  🥠 คุกกี้เสี่ยงทาย        │  header
│  แตะเลือกคุกกี้ 1 ชิ้น     │
├─────────────────────────┤
│  ┌───┐ ┌───┐ ┌───┐      │
│  │🥠 │ │🥠 │ │🥠 │      │  body: 3 แถว แถวละ 3 ไทล์
│  └───┘ └───┘ └───┘      │  ไทล์ = box มุมมน พื้นครีม
│  ┌───┐ ┌───┐ ┌───┐      │  มี 🥠 กลางช่อง + เลขกำกับเล็ก ๆ
│  │🥠 │ │🥠 │ │🥠 │      │  ทั้ง box มี action: postback
│  └───┘ └───┘ └───┘      │
│  ┌───┐ ┌───┐ ┌───┐      │
│  │🥠 │ │🥠 │ │🥠 │      │
│  └───┘ └───┘ └───┘      │
└─────────────────────────┘
```

แต่ละไทล์ตั้ง `flex: 1` เพื่อให้กว้างเท่ากันทุกช่องบนทุกขนาดหน้าจอ

**การ์ดคำทำนาย** (`lib/flex/fortune.ts`)

- header: ป้ายบอกโทน สีต่างกันตามโทน — `daily` คราม / `funny` ชมพู / `inspire` เขียว
- body: `🥠` ที่แตกแล้ว + ข้อความคำทำนาย (`wrap: true`, ขนาดใหญ่ อ่านง่าย)
- footer: ปุ่ม "เสี่ยงใหม่อีกครั้ง" → postback `a=new`

**การ์ดต้อนรับ / การ์ดใบ้วิธีเล่น** (`lib/flex/prompt.ts`)

การ์ดเรียบ ๆ บอกวิธีเล่นหนึ่งบรรทัด + ปุ่ม "เสี่ยงทายเลย" → postback `a=new`
ใช้ทั้งตอน follow และตอนผู้ใช้พิมพ์อะไรที่ไม่รู้จัก (ต่างกันแค่ข้อความพาดหัว)

### 6.5 คำเรียกเกม

normalize ข้อความก่อน (ตัดช่องว่างหัวท้าย, lowercase) แล้วเทียบกับชุดคำ:
`เสี่ยงทาย`, `เสี่ยงโชค`, `คุกกี้`, `ดวง`, `เล่น`, `fortune`

พิมพ์นอกเหนือจากนี้ → การ์ดใบ้วิธีเล่น ซึ่งมีปุ่มให้กดเริ่มเกมได้ทันที
เท่ากับผู้ใช้อยู่ห่างจากการเล่นแค่ 1 แตะเสมอ ไม่ว่าจะพิมพ์อะไรมา

### 6.6 Webhook route (`app/api/line/webhook/route.ts`)

```
export const runtime = 'nodejs'   // ต้องใช้ node:crypto ตรวจลายเซ็น
```

ลำดับการทำงาน:

1. อ่าน **raw body เป็น string** ด้วย `await req.text()` — ต้องใช้ตัวดิบเท่านั้น
   ถ้า parse เป็น JSON ก่อนแล้ว stringify กลับ ลายเซ็นจะไม่ตรง
2. ตรวจ `x-line-signature` → ไม่ตรงหรือไม่มี ตอบ **401 ทันที**
3. `JSON.parse` แล้ววน events → `handleEvent()` → ส่งผ่าน Reply API
4. ตอบ **200 เสมอ** เมื่อผ่านลายเซ็นแล้ว แม้ handler จะพัง (log ไว้ดูภายหลัง)
   ถ้าตอบไม่ใช่ 200 LINE จะยิงซ้ำ ซึ่งทำให้ผู้ใช้ได้ข้อความซ้ำ
5. รองรับ events ว่าง (`events: []`) — คือตอนกดปุ่ม Verify ใน LINE Developers Console

### 6.7 การตรวจลายเซ็น (`lib/line/verify.ts`)

HMAC-SHA256 ของ raw body ด้วย channel secret เข้ารหัส base64 แล้วเทียบกับ header
เทียบด้วย `crypto.timingSafeEqual` และเช็คความยาวก่อนเทียบ
(`timingSafeEqual` โยน error ถ้าความยาวสองฝั่งไม่เท่ากัน)

### 6.8 Environment variables

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `LINE_CHANNEL_SECRET` | ตรวจลายเซ็น webhook |
| `LINE_CHANNEL_ACCESS_TOKEN` | ยืนยันตัวตนตอนเรียก Reply API |

อ่านค่าตอน runtime และให้ fail ทันทีพร้อมข้อความชัดเจนถ้าไม่ได้ตั้งค่า
ไม่ commit ค่าจริงลง repo — ใส่ `.env.local` (gitignore) และตั้งใน Vercel dashboard

## 7. Error handling

| สถานการณ์ | สิ่งที่ทำ |
|---|---|
| ลายเซ็นไม่ผ่าน / ไม่มี header | 401 ไม่ประมวลผลต่อ |
| ไม่ได้ตั้ง env var | fail ตอนเริ่มทำงาน พร้อมบอกว่าขาดตัวไหน |
| `postback.data` ผิดรูป / `f` ไม่มีในคลัง | ตอบคำทำนายสุ่มใหม่ ไม่โยน error ให้ผู้ใช้เห็น |
| Reply API ตอบ error | log ไว้ แล้วยังตอบ 200 (กัน LINE ยิงซ้ำ) |
| event ชนิดที่ไม่รองรับ (sticker, image, ฯลฯ) | ข้ามเงียบ ๆ ไม่ตอบ |
| กดตารางเก่าที่ค้างในแชท | ทำงานปกติ — ไม่มีสถานะให้หมดอายุ |

## 8. การทดสอบ

ใช้ Vitest ตรรกะเกมทั้งหมดเป็น pure function จึงเทสต์ได้โดยไม่ต้องยิง LINE จริง

| ไฟล์เทสต์ | ตรวจอะไร |
|---|---|
| `verify.test.ts` | ลายเซ็นถูกต้องผ่าน / ผิดไม่ผ่าน / ไม่มี header ไม่ผ่าน / ความยาวเพี้ยนไม่ crash |
| `draw.test.ts` | ได้ 9 ใบ, ไม่ซ้ำกัน, มีครบทั้ง 3 โทน (โทนละ 3), rng เดิมให้ผลเดิม |
| `postback.test.ts` | encode/decode ไป-กลับตรงกัน, data ผิดรูปถูกปฏิเสธ, `f` ที่ไม่มีจริงถูกปฏิเสธ |

## 9. ขั้นตอนติดตั้ง (ยังไม่มี LINE OA — เริ่มจากศูนย์)

ทุกขั้นตอนอยู่ในแผนฟรีทั้งหมด

1. สร้าง LINE Official Account ที่ LINE Official Account Manager (ฟรี)
2. ที่ LINE Developers Console — สร้าง provider แล้วสร้าง **Messaging API channel** เชื่อมกับ OA นั้น
3. เก็บ **Channel secret** (แท็บ Basic settings) และออก **Channel access token** แบบ long-lived (แท็บ Messaging API)
4. ในแท็บ Messaging API — **ปิด** "Auto-reply messages" และ "Greeting messages"
   (ไม่งั้นบอทอัตโนมัติของ LINE จะตอบทับข้อความของเรา)
5. Deploy ขึ้น Vercel ตั้ง env var สองตัวใน dashboard
6. ตั้ง Webhook URL เป็น `https://<app>.vercel.app/api/line/webhook` → กด **Verify** → **เปิด** "Use webhook"
7. แอด OA เป็นเพื่อนจาก QR code แล้วลองเล่น

**ตอนพัฒนา** ใช้ Vercel preview deployment เป็น webhook (ฟรี อยู่ในบัญชีเดียวกัน)
แทนการใช้ ngrok ที่แผนฟรีมีข้อจำกัด ส่วนตรรกะเกมทดสอบด้วย Vitest ในเครื่องได้เลยโดยไม่ต้องต่อเน็ต

## 10. นอกขอบเขต (ตั้งใจไม่ทำ)

- ไม่มี database ไม่มี session ไม่เก็บประวัติการเล่น
- ไม่มี LIFF ไม่มีหน้าเว็บ ไม่มีอนิเมชัน
- **ไม่มี Push / Multicast / Broadcast** (จะทำให้เสียเงิน)
- ไม่จำกัดจำนวนครั้งที่เล่น
- ไม่มีคูปอง ของรางวัล หรือระบบแลกของ
- ไม่มี Rich Menu ใน v1 — เพิ่มทีหลังได้ง่ายเพราะปุ่ม Rich Menu แค่ส่งข้อความคำเรียกเข้ามา
  ซึ่ง handler รองรับอยู่แล้ว ไม่ต้องแก้โค้ด
- ไม่เก็บสถิติหรือ analytics
