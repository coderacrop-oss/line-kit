# OI-03 · ตัวเลขจริงของ LINE

เอกสาร FLEX_AD_L1 ตั้ง OI-03 เป็น Blocker ไว้ตั้งแต่ v0.1 และระบุเองว่า
**อายุ reply token ต้องวัดเอง ไม่ใช่รออ่านจากเอกสาร LINE** เพราะเขาไม่ระบุตัวเลข

ไฟล์นี้คือที่เก็บผลวัด · ตัวเลขที่ยังว่างคือตัวเลขที่ยังไม่ได้วัด

วิธีวัด: `node scripts/probe-line-limits.mjs` แล้วดู README ของสคริปต์

---

## 1 · อายุของ reply token

**ทำไมสำคัญ:** ถ้าสั้นกว่าที่ §7 เดาไว้ ต้องเลิกใช้ serverless ซึ่งกระทบ DD-05
และทุกอย่างที่วางอยู่บนนั้น · §7 ตั้งเป้า P95 < 1.5 วินาที **โดยเผื่อไว้ล่วงหน้า
ไม่ได้มาจากตัวเลขจริง**

| หน่วงกี่วินาทีก่อนตอบ | token ยังใช้ได้ไหม | รหัสที่ LINE คืน |
|---|---|---|
| 5 | | |
| 15 | | |
| 30 | | |
| 45 | | |
| 60 | | |
| 90 | | |
| 120 | | |
| 180 | | |

**สรุป:** อายุจริงอยู่ระหว่าง ___ ถึง ___ วินาที

**ผลต่อสถาปัตยกรรม:**
- [ ] ยาวพอ → อยู่กับ serverless ต่อได้ตาม DD-05
- [ ] สั้นเกิน → ต้องทบทวน DD-05 และงบเวลาใน §7 ทั้งหมด

## 2 · ขนาดสูงสุดของ Flex

**ทำไมสำคัญ:** BR-66 จำกัดการ์ดไว้ที่ 10 บล็อกและ 3 ปุ่ม โดยให้เหตุผลว่า
*"เกินแล้วขนาดข้อความเกินที่ LINE รับ ส่งไม่ออกและไม่มีข้อความบอกสาเหตุ"*
— แต่**ไม่มีที่ไหนในเอกสารระบุว่าเพดานนั้นคือเท่าไหร่**

| วัดอะไร | ค่า |
|---|---|
| Flex ที่ใหญ่สุดที่ LINE รับ | ___ bytes |
| ข้อความปฏิเสธที่ได้ | |
| 10 บล็อกตาม BR-66 ใหญ่ประมาณ | ___ bytes |
| เหลือระยะเผื่อ | ___ % |

**ถ้า 10 บล็อกกินเพดานเกินครึ่ง** ควรลด BR-66 ลง หรือย้ายไปวัดเป็น bytes
แทนการนับบล็อก

## 3 · ที่ยังต้องเปิดเอกสาร LINE อ่านเอง

สคริปต์วัดสองข้อบนให้ได้ แต่สามข้อนี้ต้องไปอ่าน — ผมดึงหน้าอ้างอิงของ LINE
ไม่สำเร็จหลายรอบ (หน้าเดียวขนาดใหญ่ ตัวดึงตัดเนื้อหาทิ้ง บางหน้าตอบ 403)

เปิด `developers.line.biz/en/reference/messaging-api/` แล้วค้นหัวข้อในวงเล็บ

| ยังไม่รู้ | หาที่ไหน | เกี่ยวกับกฎข้อไหน |
|---|---|---|
| ขนาดไฟล์สูงสุดของภาพเมนู | *Requirements for rich menu image* | OI-23 |
| กฎสัดส่วนภาพของเมนู | *Requirements for rich menu image* | OI-23 |
| จำนวนช่องสูงสุดของริชเมสเสจ | *Imagemap message* | BR-47 |

**ที่ยืนยันแล้วและใส่เอกสารไปแล้ว** — ภาพเมนูเป็น JPEG หรือ PNG · กว้าง 800
ถึง 2500 · สูงอย่างน้อย 250 · ขนาดแนะนำ 2500 × 1686 · ช่องกดสูงสุด 20 ช่อง ·
อัปโหลดภาพเมนูใช้โดเมน `api-data.line.me` · แขวนแบบยกชุดจำกัด 3 ครั้งต่อชั่วโมง

## ข้อควรระวังตอนวัด

**ใช้บัญชีทดสอบเท่านั้น** — สคริปต์ตอบข้อความกลับและอาจส่ง push · ยิงเข้าบัญชี
ลูกค้าแล้วจะกลายเป็นข้อความทดสอบในแชทจริงซึ่งลบไม่ได้ ตรงกับที่ BR-62 ห้ามไว้

**การวัด reply token กินโทเคนละหนึ่งครั้งต่อการทดลอง** — โทเคนใช้ได้ครั้งเดียว
จึงต้องพิมพ์เข้าไปหนึ่งครั้งต่อหนึ่งค่าในบันได

**การวัดขนาด Flex ใช้ push ซึ่งมีค่าใช้จ่าย** — ปิดไว้เป็นค่าเริ่มต้น ต้องตั้ง
`PROBE_ALLOW_PUSH=1` เอง · บนบัญชีทดสอบไม่กี่สิบข้อความยังอยู่ในโควตาฟรี
