4.2 วิธีคำนวณของ resolve แต่ละแบบ

ส่วนนี้ต้องนิยามให้ชัดที่สุดในเอกสาร เพราะ L0 บอกว่าแต่ละแบบคืออะไร แต่ไม่ได้บอกว่าคำนวณยังไง · สองคนเขียนอาจได้ผลต่างกันถ้าไม่มีตารางนี้

ขั้นตอนร่วมของทุกแบบ

1. ดึงรายการผลลัพธ์จาก activity.resolve_config.outcomes[] 2. ตัดผลลัพธ์ที่ผูกกับรางวัลที่หมดแล้วออก ← reward.quota - issued_count <= 0 └── ถ้าถูกตัดจนไม่เหลือเลย → คืน activity.fallback_card_id (BR-31) 3. ตัดสินตามวิธีที่เลือก (ตารางด้านล่าง) 4. คืน outcome.id + การ์ดที่ผูก 5. บันทึก play_lock.result เพื่อคืนผลเดิมเมื่อกดซ้ำ (BR-32)

fixed — เลือกอะไรได้อันนั้น

outcome = outcomes.find(o => o.id === ตัวเลือกที่ผู้ใช้กด) เงื่อนไขบังคับ: จำนวน outcomes ต้องเท่ากับจำนวนช่องที่ผู้ใช้เลือกได้พอดี ตรวจตอนบันทึกกิจกรรม ไม่ใช่ตอนรัน

weighted — สุ่มตามน้ำหนักคงที่

total = ผลรวมของ weight ทุก outcome ที่เหลืออยู่ r = สุ่มเลขจริงในช่วง [0, total) ไล่สะสม weight จนกว่า acc > r → ได้ outcome นั้น ตัวอย่าง weight 2 · 3.5 · 4.5 → total 10 r = 4.2 → acc: 2 (ไม่ถึง) → 5.5 (เกินแล้ว) → ได้ตัวที่สอง หมายเหตุ weight เป็นค่าดิบ ไม่ใช่เปอร์เซ็นต์ · หน้าจอคำนวณ % ให้ดูเฉยๆ weight = 0 แปลว่าไม่มีวันออก แต่ยังแสดงในรายการได้

quota — สุ่มตามของที่เหลือ

ยังไม่ตัดสินว่าใช้สูตรไหน — ดู OI-18 ใน §10 · ทั้งสองแบบให้ผล "กระจายรางวัลใหญ่ตลอดแคมเปญ" เหมือนกัน แต่พฤติกรรมต่างกันชัดเจน

แบบสูตรพฤติกรรม

ข · น้ำหนักตามอัตราการจ่ายที่ควรเป็นweight = remaining ÷ เวลาที่เหลือกระจายสม่ำเสมอตลอดแคมเปญจริง · แต่ต้องรู้เวลาที่เหลือและประมาณจำนวนคนเล่น

ข้อเสนอ — ใช้แบบ ข โดยคำนวณจาก เวลาที่เหลือถึง campaign.end_at เทียบกับเวลาทั้งหมด ซึ่งมีข้อมูลครบอยู่แล้วโดยไม่ต้องประมาณจำนวนคน · แต่ต้องยืนยันก่อนเขียนโค้ด

score — รวมคะแนน มีสองแบบ

แบบ 1 · แยกตามผลลัพธ์ ใช้กับแบบทดสอบบุคลิก แมทช์สัตว์เลี้ยง ทุกตัวเลือกที่ผู้ใช้กด ให้คะแนนกับ outcome หลายตัวพร้อมกันได้ รวมคะแนนแยกกองตาม outcome → outcome ที่คะแนนสูงสุดชนะ คะแนนเท่ากัน → เอา outcome ที่อยู่บนสุดในตาราง (tie_breaker = first) แบบ 2 · รวมกองเดียว ใช้กับเกมทายภาพ ทดสอบความรู้ ทุกตัวเลือกให้คะแนนเป็นตัวเลขเดียว รวมทั้งหมด หา outcome ที่ range_min <= คะแนนรวม <= range_max ช่วงต้องไม่ทับกันและต้องครอบคลุมทุกคะแนนที่เป็นไปได้ — ตรวจตอนบันทึก
