## 4b · สาม branch ที่ค้างไว้ — รวมเข้ามาแล้วทั้งหมด

งานค้างของ 11 · 15 · 18 ทำจนจบและ merge เข้า branch นี้แล้ว ทั้งสาม worktree ไม่มีอะไรค้าง
ชั้นข้อมูลของเดิม**เก็บไว้ทั้งหมด** ไม่มีตัวไหนที่อ่านแล้วต้องเขียนใหม่

```

3485545  Task 15  M7-S01 · M7-S02    mutate 41 จุด · เทสต์อ่อน 4 · บั๊กจริง 3
dd91140  Task 18  M1-S03 · M13-S02   mutate 45 จุด · เทสต์อ่อน 3 · บั๊กจริง 3
```

**บั๊กที่จับได้เพราะเขียน integration test บนตารางจริง ไม่ใช่ mock**

- `saveEntryRule` เก็บคีย์ที่ engine ไม่ได้อ่าน (`key`/`value` แทน `rewardCode`/`activityCode`/`count`)
  → เงื่อนไขทางเข้าเป็นเท็จกับทุกคนตลอดกาล **แคมเปญกันผู้เล่นออกหมดโดยไม่มี error ที่ไหนบอก**
- `loadActivity` เลือก `card.name` ที่ไม่มีคอลัมน์นั้น → จอ M7-S02 พังตั้งแต่โหลด · typecheck จับไม่ได้เพราะ SQL เป็นสตริง
- จอผู้ใช้แสดงปุ่มถอนสิทธิ์ให้ทุกบทบาท ทั้งที่ action ปฏิเสธเสมอ

**เทสต์ที่นับทั้งตารางจะแกว่งเมื่อไฟล์ integration รันขนานกัน** — `duplicate.integration` เคยนับ
`count(*) FROM campaign` ทั้งตาราง แล้วแดงเพราะไฟล์อื่นแทรกแถวระหว่างนั้น · แก้เป็นนับเฉพาะ
รหัสของตัวเองแล้ว · `channels.integration` ยังนับ `token_access_log` ทั้งตารางอยู่ ตอนนี้ยังไม่มีใครชน

## 7 · วิธีทำงานที่ใช้อยู่ ได้ผลดี

**ยิง subagent ทีละ task** พร้อมคำสั่งสามข้อที่ทำให้จับบั๊กได้จริง

1. **TDD จริง** — เขียนเทสต์ → ดูให้แดง → เขียนโค้ด → ดูให้เขียว → commit
2. **mutate โค้ดพิสูจน์ว่าเทสต์แดง** แล้วย้อนกลับ · รายงานทุกจุด · **ตัวที่รอด = เทสต์อ่อน ต้องเขียนใหม่**
3. **ก่อนรายงานปัญหา ให้ตรวจกับโค้ดจริงไม่ใช่กับแผน**

agent ที่ผ่านมา mutate รวมกว่า 440 จุด เจอเทสต์อ่อน 27 ตัว และ**บั๊กจริง 13 ตัว**

**ยิงขนานต้องใช้ worktree** — ถ้ายิงหลายตัวบนรีโปเดียวกันจะชน `git index.lock` และ `.next`
⚠️ **ตรวจทุกครั้งว่า worktree ตัดมาจาก branch ถูก** — รอบที่แล้วตัดจาก `main` ซึ่งเป็นโปรเจกต์เก่าคนละตัว
