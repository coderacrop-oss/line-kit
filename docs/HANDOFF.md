## 7 · วิธีทำงานที่ใช้อยู่ ได้ผลดี

**ยิง subagent ทีละ task** พร้อมคำสั่งสามข้อที่ทำให้จับบั๊กได้จริง

1. **TDD จริง** — เขียนเทสต์ → ดูให้แดง → เขียนโค้ด → ดูให้เขียว → commit
2. **mutate โค้ดพิสูจน์ว่าเทสต์แดง** แล้วย้อนกลับ · รายงานทุกจุด · **ตัวที่รอด = เทสต์อ่อน ต้องเขียนใหม่**
3. **ก่อนรายงานปัญหา ให้ตรวจกับโค้ดจริงไม่ใช่กับแผน**

agent ที่ผ่านมา mutate รวมกว่า 610 จุด เจอเทสต์อ่อน 33 ตัว และ**บั๊กจริง 20 ตัว**

**ยิงขนานต้องใช้ worktree** — ถ้ายิงหลายตัวบนรีโปเดียวกันจะชน `git index.lock` และ `.next`
⚠️ **ตรวจทุกครั้งว่า worktree ตัดมาจาก branch ถูก** — เคยตัดจาก `main` ซึ่งเป็นโปรเจกต์เก่าคนละตัว
⚠️ **ห้าม symlink `node_modules` เข้า worktree แล้ว `git add -A`** — `.gitignore` กันไว้แล้วทั้งสองรูปแบบ แต่ให้ระบุ path ตอน add เสมอ
⚠️ **ฐานข้อมูล `linekit_test` ใช้ร่วมกันทุก worktree** — ห้าม `db:reset` ระหว่างที่ agent ตัวอื่นรัน · และห้ามเขียนเทสต์ที่นับทั้งตาราง

## 9 · หนี้ทางเทคนิคที่หนักสุดสามข้อ

1. **ระบบพูดแทน OA ได้ตัวเดียว — ปลดไปครึ่งหนึ่งแล้ว** · `setWebhookEndpoint` รับโทเคนเป็นพารามิเตอร์
   และเส้นทางส่งขึ้นเรียกผ่าน `readChannelSecret(purpose:'publish')` ซึ่งเป็นผู้เรียกรายแรกของฟังก์ชันนั้น
   **แต่ `replyMessage` ยังอ่าน env อยู่** เส้นทางตอบผู้เล่นจึงยังพูดแทน OA ได้ตัวเดียว · ทำตามแบบของ `setWebhookEndpoint`
2. 🔴 **`channel.line_channel_id` ไม่มีหน้าจอกรอก — ตอนนี้รู้ราคาแล้ว** · `lib/db/queries.ts` หาแคมเปญจาก
   `WHERE ch.line_channel_id = <destination>` และบัญชีที่สร้างจากจอ M6-S02 มีค่านี้เป็น NULL เสมอ
   → **ตั้ง webhook สำเร็จ แต่ event ที่ยิงกลับมาหาแคมเปญไม่เจอ บอทเงียบทั้งที่จอบอกว่าส่งขึ้นแล้ว**
   จอ M1-S04 เตือนไว้แต่ไม่บล็อก เพราะไม่มีจอไหนให้กดไปแก้ · **เติมช่องนี้ในจอ M6-S02 คือหนี้ที่คุ้มที่สุดที่จะจ่าย**
   · และเพราะคอลัมน์เป็น UNIQUE แบบ nullable ซึ่ง NULL ไม่ชนกันเองใน Postgres แถวที่ยังไม่มีรหัสจึงมีกี่แถวก็ได้ BR-68 มองไม่เห็น
3. **หน้า login ไม่มีสามสถานะ** — แผนสั่งไว้เองแล้วไม่ได้ทำ · `devLogin` โยน error ทั้งสองกรณี ผู้ใช้เจอหน้า error ของ Next
